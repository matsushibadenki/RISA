# G3.4 Cold probes and payback / 冷候補調査と費用回収 / 冷候选探测与成本回收

## 日本語

実運用queryログはリポジトリで見つからず、今回の入力は開発用worldのqueryである。運用分布の検証完了とはしない。以前の単一action集中fixtureから離れ、G3.4の独立worldと結合worldで実composerを実行し、各queryが実際に参照したPrimitiveの回数を記録した。学習seed17・32 episode、評価queryは別identity/seed29。未知経路、役割を交差させた反例、identity反例、状態不足、共有資源不足、actor役割欠落を含み、candidate無効/有効を比較する。

`rebalance_primitive_grounding`は、当該区間の参照0かつ費用未調査の線形候補を調査しないようにした。`lookup_cost=None`を維持し、その候補は今回の割当から除外する。後続区間で参照されれば調査し、確認条件を満たせば昇格できる。既存lookupと費用が既知の候補は引き続き割当に参加する。`probe_cold_candidates=True`で旧来の全候補調査を再現できる。既存の頻度/安定化benchmarkはこの指定で過去の比較手順を維持した。

この変更は、確認待ち区間で全冷候補の辞書を作って捨てる費用を削る。一方、最初に参照された候補の費用調査は確認前に必要であり、省略していない。未調査の冷候補を空き予算へ先回りで詰めなくなるため割当は旧方式と異なり得るが、同じwitness行による線形検索が残り、意味上の結果は維持する。総予算の定義、保存schema、既定の全走査とID順policyは変えない。

比較は同じ2,320-byte予算のID順・旧全候補調査（eager）・冷候補保留（lazy）。後2方式は連続確認2。測定Pythonでは1辞書1,160 bytes、2辞書が収まる。6区間は「identity/役割拒否」2区間、「既知/未知の経路」2区間、「全panel」2区間。各query群を1/8回繰り返す2密度を使用する。1倍では各区間8/8/16/16/40/40 query、合計128、8倍は合計1,024 query。第3区間前に1 episode追加、第5区間前にidentity訂正・無効化する。将来の区間の参照回数は割当に使わない。

9つの新規processを逐次起動（hash seed0/1/42 ×3先行順）、各processで2 world ×2密度を比較する。CPUとwallの総費用は初期構築＋追加学習＋query（訂正後の再構築を含む）＋全再配置。最後の区間の再配置も含む。全timed queryとタイマー外の反例panelを全走査の完全結果に照合し、反例検証のquery計数は復元する。全区間で保存用state一致、最後に実保存バイト列・復元結果を確認する。検証・保存の時間は総費用外。

費用回収は各processの対応するID順を基準とする。`S = IDのquery CPU − 対象方式のquery CPU`、`C = 対象方式の構築/学習/再配置CPU − IDの同費用`。観測区間で`S > C`なら総費用を回収した。`S > 0`の場合だけ、事後平均の損益分岐query数を`max(0,C)/(S/N)`として記録し、`S <= 0`はnullとする。この数値は同じ平均差が続く仮定であり、将来予測や自動policy閾値ではない。小さい時間差にはGC・実行順・計測雑音が含まれるため、回収したprocess数も示す。

## English

No production query log was found or supplied. This evaluates development-world queries through the real composer, not production usage. Train32 episodes with seed17 and evaluate distinct identities/seed29 in independent and coupled G3.4 worlds. Include novel paths, crossed roles, identity, missing-state/resource and missing-actor-role counterexamples, with candidates both disabled and enabled. Record the actual per-Primitive accesses caused by composition, rather than prescribing single-action hit counts.

By default, rebalance skips unknown-cost linear candidates with zero accesses in the current window. Leave their cost unknown and exclude them from this allocation; later accesses trigger probing and allow promotion. Retained lookups and known costs still participate. `probe_cold_candidates=True` reproduces eager exploration; older benchmarks explicitly request it. This avoids constructing cold dictionaries during confirmation waits, but still probes newly accessed candidates before confirming an allocation. Allocation may differ because unknown cold candidates no longer fill spare capacity; exact row fallback preserves semantics.

Compare ID/eager/lazy at2,320 bytes; eager/lazy use confirmation2. Six windows repeat rejection, valid/novel paths, and full-panel query groups twice each. Density1 gives128 queries total; density8 gives1,024. Append an episode before window3 and correct identity before window5. Nine fresh serial processes cover three hash seeds and three cyclic arm orders; each runs two worlds/two densities. CPU/wall total includes build, learning, query/cold rebuilding and all rebalances, including the last one. Verify every timed result and the full counterexample panel against full scan outside timing, restoring hit counters. Check serialized state each window and actual saved bytes/reloads at the end.

For each paired process, query savings S = ID query CPU minus policy query CPU; extra maintenance C = policy build/train/rebalance CPU minus ID equivalents. Observed payback requires S>C. Only for S>0, report the retrospective average break-even query count max(0,C)/(S/N); otherwise null. This extrapolates the observed average, not future behavior or an automatic threshold. Report recovered-process counts because small differences include GC/order/timer noise. Saving and verification are outside total costs.
