## Quality and the discovered applicability problem

Every seed/checkpoint/partition gives:

| Metric | Result |
| --- | --- |
| Induced-role prediction | 24/24 correct |
| Role induction disabled | 8/24 correct |
| Composition, candidates on | 16/24 correct |
| Composition, candidates off | 16/24 correct |
| Invalid composition cases | 16 |
| False accepts, candidates on/off | 8/16 for each |
| Unsupported-relation false accepts | 4 for each |
| Reverse-relation false accepts | 4 for each |
| Missing-state / insufficient-energy false accepts | 0 for each |

The false accepts return an `online` composition path for a novel target related by `stored_in`, or with `powered_by` pointing toward rather than away from the target. Both are invalid under the frozen world truth table. Input binding names differ from training. State/numeric negative controls are rejected correctly. Prediction and composition therefore have different applicability behavior in this fixture; the cause and intended unknown-role fallback require code-level review before changing production behavior.

Development/final have 72 distinct cases each across seeds, repeated at three checkpoints (216 evaluations per partition, not 216 independent cases). All entity/actor/ID namespaces are disjoint from training and each other. Target roles are not supplied in training or queries; relation features drive induction. Separate generator implementations share a world specification, so distribution-level independence is not established. This tests two-step composition of learned actions, not learning novel action identities or arbitrary longer compositions.

The predeclared prediction gain passes; candidate-enabled composition gain is zero; active/adopted growth and marginal-storage reduction fail. Candidate on/off have equal false acceptance, so the relative no-increase condition passes while absolute correctness remains unacceptable. Do not use a relative ablation metric to hide the eight invalid acceptances.
