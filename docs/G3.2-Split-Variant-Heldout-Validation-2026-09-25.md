# G3.2 split-variant held-out validation / 分裂variant独立検証 / 分裂变体独立验证

Status: [Done] read-only development audit; changing Primitive adoption remains [Next].

The [split-variant validator](../risa/evaluation/split_variant_validation.py) evaluates context-split Primitives with labels that are disjoint from learned Events, scoring probes and candidate-lifecycle evidence. It requires an exact action and complete context match, uses unseen actors and targets with the same supplied target role, records unique labels consumed, and does not mutate the model. The fixed development manifests provide eight labels for each B context, for 16 available labels per seed. A label is counted once even when competing effect variants use it.

| Condition and arm | Variant opportunity | Labels consumed | Adopted variants failing held-out validation, five seeds |
| --- | --- | --- | --- |
| Clean, all arms | No split variants | 0 | 0, 0, 0, 0, 0 |
| 20% noise, split off | No split variants | 0 | 0, 0, 0, 0, 0 |
| 20% noise, regular split on | Two variants in seed 71 only | 16 in seed 71 | 0, 0, 0, 0, 0 |
| 20% noise, optional contextual split | Four variants in every seed | 16 per seed | 2, 1, 2, 1, 0 |

For the optional contextual split arm, the independent labels identify every variant that the synthetic latent-rule audit classifies as off-rule. Passing adopted variants number 2, 3, 2, 3 and 4. This agreement is expected in this deterministic single-effect world; it verifies evidence separation and accounting, rather than establishing a general validation threshold. The held-out panel is intentionally noiseless and therefore does not estimate robustness to validation-label noise.

The audit runs after B and does not alter `adopted`, prediction, recovery or retention. Connecting it to adoption now would spend supervised labels after observing the result and would not establish predictive benefit: previous interventions show that split on/off trajectories are identical in this fixture. A future opt-in adoption experiment must preregister validation timing, label noise, minimum labels, acceptance confidence, shared label caps and a prediction-effect gate. The current default adoption logic is unchanged.

A read-only gate intervention now confirms the prediction-effect boundary directly. On a disposable state copy, every adopted held-out failure is marked non-adopted and the four independent A plus four independent B probes are rescored. In the 20% noise contextual-split arm, **2, 1, 2, 1 and 0 variants are rejected, but zero of 40 paired predictions change**; accuracy remains 1.0 before and after for every seed. Clean and other arms reject nothing and also remain unchanged. The intervention itself is covered by a counterexample where rejecting the only applicable Primitive changes a prediction to abstention, so the zero result is specific to this fixture rather than an inert evaluator.

This closes the current split-adoption branch: implementing a supervised adoption gate here would add 16 labels per active seed without measurable prediction benefit. Split validation remains measurement infrastructure. G3.2 development priority moves to whether adopted merge/dormancy structures contribute to predictions before drift invalidates them.
