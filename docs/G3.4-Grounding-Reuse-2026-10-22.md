# G3.4 Calibration reuse / 計測値の再利用 / 计测值复用

## 日本語

前回の総時間悪化を受け、まず同じ仕事を再計測する費用を削減した。`calibrate_grounding_benefits(..., reuse=True, max_reuses=2)`は、計測に成功した候補について、照合例の内容と順序、round数、反復数、辞書予算が同じ場合に保存済みの計測値を返す。最大2回の再利用後は再計測する。回数は候補ごとの明示的な再利用API呼出し単位であり、wall時間のTTLではない。既定の`reuse=False`は毎回計測を維持する。

追加支持のjoint actor役割/target役割/identity行が既存集合に含まれる場合、同じPrimitive・同じrowsオブジェクトで行数不変を確認し、辞書費用と計測値を保持する。行が増える場合、owner置換、支持数不整合、訂正・再構築・復元は計測値を失効させる。rows集合全体のコピーやhash計算は追加せず、appendの増分性を維持する。予算超過で計測に成功しなかった候補は再利用対象外。

照合例は最大64件までしか消費せず、役割列をtupleに固定して比較する。再利用だけのcalibration呼出しでは連続確認をリセットしない。append時の確認リセットは従来どおり。元の計測・構築費用の見積りは再利用時にも保持し、既に支払ったからといって予測上の昇格費用を0にはしない。保存schema・query判定・通常queryの処理は変更しない。計測cacheは一時メモリであり、辞書bytes予算には含まれない。

比較ではID・頻度・毎回計測（fresh）・再利用（reuse）の4方式を用いる。前回と同じ独立/結合/集中world、各32/512 queryの4区間。1/2/3区間目で過去の先頭8照合例を採取しAPIを呼ぶ。2区間目は同じ分布、3区間目前に追加学習（小worldは既存行への支持、集中worldは新しいwitness）、4区間目前にidentity訂正する。全方式のquery列・更新・予算は同じ。毎回方式は新しいAPIの`reuse=False`を使うため、比較は同一コード上の再利用有無であり、前回commitの再測定ではない。

3 hash seed ×4巡回先行順の12 processを逐次実行。例の採取・再利用判定・計測・構築・更新・検索・最終区間を含む再配置をCPU/wallへ計上する。各timed queryと反例panelの完全結果、区間ごとの保存用state、実保存/復元を確認する。process間は完全結果digestと、既存graph edge配列順のみを正規化した保存内容を比較する。計測による配分はprocess間で同一とは限らない。

再利用は照合例の代表性を保証しない。同じ先頭8例でも後続query分布は変わり得るし、CPUの実行環境も変わる。最大再利用回数は測定の鮮度を制限するだけで、最適な間隔を自動選択しない。実運用ログは未提供。今回の段階では、標本化の偏りの改善や実運用での自動制御まで完了とはしない。

## English

Add opt-in `reuse=True, max_reuses=2` to explicit calibration. Reuse successful measurements only when ordered binding samples, rounds, repetitions and budget match; refresh after two reuse calls. This is a call-count limit, not a wall-time TTL. Default `reuse=False` still measures every call.

Preserve dictionary costs and calibration across incremental support additions only when the same primitive/rows object retains the same joint-row count. New witness rows, replacement, support-count mismatch, correction/rebuild/load invalidate estimates. No whole-row copies or hashes are added to append. Over-budget unsuccessful measurements are not cached for reuse. Consume at most64 samples and freeze role sequences as tuples. Reuse-only calls preserve confirmation history; append retains its previous confirmation reset. Keep original setup estimates rather than assuming future promotion is free. Cache remains transient, outside dictionary-container budgets; query semantics/persistence are unchanged.

Compare ID/frequency/fresh/reuse on the prior independent/coupled/concentrated worlds, four windows of32/512 queries. Collect the first eight past bindings and call calibration in windows1/2/3. Window2 repeats the distribution; append before window3 adds existing support on small worlds and a new row on the concentrated world; correct identity before window4. Fresh uses the current API with reuse disabled, isolating reuse rather than reproducing the previous commit. Twelve serial processes balance three hash seeds/four cyclic orders. Include capture/check/calibration/build/train/query/rebalance CPU/wall costs. Verify timed queries and counterexamples, state checkpoints, actual saved bytes/reloads and cross-process full-result/edge-order-normalized content digests.

Matching prefixes do not prove future distribution stability or CPU timing stability. The reuse cap bounds age in calls, not an optimal cadence. Production logs remain unavailable; sampling-bias correction and automatic operational control remain unfinished.
