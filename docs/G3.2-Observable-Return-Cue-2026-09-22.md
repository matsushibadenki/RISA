# G3.2 observable return cue / 観測可能な復帰手掛かり / 可观察返回提示

Status: [Done] development control; the G3.2 causal gate remains [Next].

The [clean](../experiments/g3_contextual_return_cue_clean_manifest.json) and [20% observation-noise](../experiments/g3_contextual_return_cue_20_manifest.json) manifests use the same five development seeds, Event counts, latent rules and noise schedule as the prior uncued stress test. They add `regime:A` to every A1/A2 Event and A probe, and `regime:B` to every B Event and B probe. This is an **externally supplied, observable regime cue**; it contains no effect label and is available identically to RISA, the latest-outcome table and a new per-key outcome-count table. The return cue is present before the A2 entry probe, so no A2 learning is needed to read it. A1/A2 share the same cue. Exact-query conflict count is zero, and the A accuracy ceiling under perfect B prediction is 1.0.

The count baseline stores all observed outcome frequencies for each action, supplied role set and context-tag set; it chooses the most frequent outcome and breaks ties by most recent observation. This is a stronger deterministic comparator under label noise than a latest-only table. Both tables see precisely the same Events and probe roles as RISA. No model is tuned by seed.

| Condition | Model | B exit latent accuracy | A2 entry A retention | B recovery Events, five seeds |
| --- | --- | --- | --- | --- |
| Clean | Latest table / count table / all RISA arms | 5/5 at 1.0 | 5/5 at 1.0 | 4, 4, 5, 4, 3 |
| 20% noise | Latest table | 2/5 at 1.0; 3/5 at .5 | 5/5 at 1.0 | 4, 4, 5, 4, 11 |
| 20% noise | Count table | 5/5 at 1.0 | 5/5 at 1.0 | 4, 4, 5, 4, 11 |
| 20% noise | RISA split on/off/contextual | 5/5 at 1.0 | 5/5 at 1.0 | 4, 4, 5, 4, 3 |

The B probe trajectory mean over 21 boundary/observation points is .810, .690, .667, .690, .738 for the latest table; .905, .905, .881, .905, .762 for the count table; and .905, .833, .881, .857, .810 for each RISA arm. These are paired descriptive measurements, not confidence intervals or a final test. The count table matches RISA's B exit accuracy and A retention, while the two differ in early adaptation on individual seeds. In the clean control all three model types have identical B recovery and A retention.

RISA's split on, split off and optional contextual split arms again have identical prediction trajectories and recovery counts. Noise triggers splits in some enabled arms, but they produce no measured prediction benefit. The cue makes return retention identifiable, yet a simple count table already reaches the ceiling. This world is a valid **cue and baseline control**, not evidence for structural condensation or split causality. Its supplied regime tags also make A/B routing unusually easy; future development worlds must test a less direct cue and preserve this control and the uncued negative world.

Result artifacts: [clean](g3-contextual-return-cue-clean-results.json) and [20% noise](g3-contextual-return-cue-20-results.json). Serialized table bytes are model-state payloads only; RISA Event history and Replay make a direct storage comparison inappropriate here.
