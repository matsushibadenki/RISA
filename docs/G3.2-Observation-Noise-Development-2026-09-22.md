# G3.2 observation noise development / 観測ノイズ開発実験 / 观测噪声开发实验

Status: [Done] development stress test. G3.2 mechanism attribution remains [Next].

The [clean](../experiments/g3_contextual_observation_noise_clean_manifest.json) and [20% noise](../experiments/g3_contextual_observation_noise_20_manifest.json) manifests were fixed before running five paired development seeds (11, 23, 37, 53, 71). A1 has 10 clean Events. B and A2 have 20 Events each, with 10 indoor and 10 outdoor observations. In the noise condition, exactly two observed effects per context per phase are flipped; independent probes always score the latent rule. B changes only indoor from warm to cold, and A2 returns it to warm. The same Event order and labels feed the role-conditioned latest-outcome table and each RISA arm. The clean control has identical Event IDs, order and contexts. This is a label-noise stress test, not a claim that the environment itself randomly switches.

| Condition | Model | B recovery Events, five seeds | A2 entry A accuracy / A1, five seeds | B exit latent-probe accuracy, five seeds | A2 recovery Events, five seeds |
| --- | --- | --- | --- | --- | --- |
| Clean | Latest role/context table | 2, 4, 5, 4, 3 | .5, .5, .5, .5, .5 | 1, 1, 1, 1, 1 | 6, 4, 2, 2, 3 |
| Clean | RISA split on/off/contextual | 6, 10, 11, 9, 12 | .5, .5, .5, .5, .5 | 1, 1, 1, 1, 1 | 7, 6, 4, 5, 7 |
| 20% noise | Latest role/context table | 2, 4, 5, 4, 11 | .5, 0, .5, 0, 1 | 1, .5, 1, .5, .5 | 6, 4, 2, 5, 0 |
| 20% noise | RISA split on/off/contextual | 6, 12, 10, 14, 14 | 1, .5, 1, 1, 1 | .5, 1, .5, .5, .5 | 0, 4, 0, 0, 0 |

In the noisy condition, RISA retains more A accuracy at the return boundary in four seeds and ties in one, but this coincides with incomplete B adaptation: B exit accuracy is .5 in four seeds. A2 `recovery_events = 0` in four seeds means the A probe was already correct before any A2 Event; it must not be described as faster relearning. The table adapts faster to clean B and has higher B exit accuracy in the noisy condition. RISA's split on, split off and optional contextual proposal arms have **identical probe trajectories and recovery counts** in both conditions. With noise, split execution differs (0, 1 or 2 per seed), but that difference has no measured predictive benefit here. This experiment does not establish a causal value for split, merge or dormancy, and does not pass the G3.2 opportunity gate.

The new adaptation-qualified retention audit sharpens that reading. At the B exit threshold of .95, all five clean seeds qualify for both models and each retains .5 of its A1 accuracy. Under 20% noise, the latest table qualifies on seeds 11 and 37; RISA qualifies only on seed 23. Each qualifying row has retention .5, and **no noisy seed qualifies for both models**. Therefore, the higher raw A-return retention cannot support a paired claim that RISA preserves learned A knowledge better after successful B adaptation. Every nonqualifying row remains in the result artifact with raw retention and its B exit accuracy.

An exact-query identifiability audit finds that two of the four A probes have the **same complete query** as B probes but demand the opposite effect. The model sees no new observation or phase cue between B exit and A2 entry. Consequently, if it answers all B probes correctly, it can answer at most two of the four A probes correctly at that instant. The observed .5 retention after clean B adaptation equals this ceiling; it does **not** measure whether the old A rule remains stored but inaccessible. Even an oracle transition model receiving only these queries cannot beat the ceiling in both panels at the same state. The audit checks exact input identity and does not assert identifiability when queries differ.

The result artifacts are [clean](g3-contextual-observation-noise-clean-results.json) and [20% noise](g3-contextual-observation-noise-20-results.json). `online_pre_update_success` in the existing runner is agreement with the *observed* label, including flipped labels. Latent-rule accuracy is represented by the independent `probe_accuracy_by_observed_events` trajectories. The baseline stores the latest outcome; RISA also retains Event history and performs Replay, so this paired prediction comparison is not an equal-memory cost comparison.
