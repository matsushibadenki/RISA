# G3.4 direct composition work measurement

## English

### Instrumentation contract

`compose_to_effect(..., search_diagnostics=work)` optionally fills a caller-owned dictionary. It resets that dictionary for every query and does not change `CompositionResult`, persistent state or default return behavior. No persistence schema changes. Counters are:

| Counter | Definition |
| --- | --- |
| `expanded_nodes` | Ordinary-search queue entries popped, including dead ends |
| `primitive_scan_count` | Stored Primitive entries visited by ordinary selection, including rejected entries |
| `eligible_primitives` | Selected stored/derived Primitive entries returned by selection |
| `successor_candidates` | Successor action entries iterated before depth pruning |
| `plan_candidates` | Role-matched adopted plans returned for constraint filtering; not all index probes |
| `candidate_step_attempts` | Macro step transition attempts, including failed applications |
| `transition_checks` | Transition-kernel calls in selection and execution, including repeated feasibility checks |
| `grounding_event_reads` | Successful Event-record retrievals by ordinary actor/target grounding; repeated retrievals counted |

The instrumented selection list still scans its original Primitive collection. Role grounding still reads original primary evidence; no access optimization is hidden in this measurement. Counters cover these selected operations, not all CPU/memory work: initial role induction, candidate index lookup internals, graph adjacency traversal and allocation costs are not fully counted. Event reads are logical in-memory record accesses, not disk reads. Counters must not be summed into an assumed equivalent unit cost.

Adopted macro execution can pop zero ordinary queue nodes but still applies transitions. A dedicated counterfactual scoring test confirms two macro-step/kernel attempts instead of calling that zero work. This test forces a validated-path setup only for instrumentation; production adoption rules are unchanged.

### Fixed fixture rerun

The preceding v2 manifest and all its quality thresholds remain unchanged. Three seeds × three Event checkpoints × 40 cases compare RISA candidate-on/off and the learned grounded table/simple BFS. Instrumented and uninstrumented **complete CompositionResults agree** for every RISA query. Reload results also agree and held-out evaluation leaves learned state unchanged. All three quality paths remain40/40 with zero false accepts, and no candidate is adopted.

Counts below are per seed, per 40-case panel; candidate-on and candidate-off are identical:

| Events | RISA expanded nodes | RISA Primitive scans | RISA kernel checks | RISA grounding Event reads | Table expanded nodes | Table contract scans | Table kernel checks |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | 48 | 96 | 40 | **288** | 48 | 184 | 24 |
| 16 | 48 | 96 | 40 | **576** | 48 | 184 | 24 |
| 32 | 48 | 96 | 40 | **1,152** | 48 | 184 | 24 |

RISA also reports16 eligible Primitives and8 successors per panel. The table's learned contracts avoid primary Event retrieval during query execution, although its stored payload retains raw Events. The two search implementations share transition semantics but have different scan units. Neither equal queue nodes nor differing scan/kernel counts establish wall-clock superiority.

The central finding is that **constant structure/search-node counts hide linearly increasing grounding evidence work** in this repeated-world fixture. Primary support grows with Event count and the corrected actor/target grounding helpers rescan it. This is not a demonstration of decreasing query work or knowledge condensation. The pilot has only8–32 Events; no100k extrapolation or latency claim follows.

## 日本語

`compose_to_effect(..., search_diagnostics=work)`にqueryごとにリセットする任意の診断dictを追加した。通常探索のqueue展開、Primitive全検査、適用候補数、後続action、role一致plan、macro step試行、transition-kernel呼び出し、役割接地の成功Event取得を直接計数する。完全CompositionResult・保存schema・学習状態は変更しない。候補macroは通常node展開0でもstep/kernal実行を別計測し、仕事量0とは扱わない。

v2固定fixtureの3 seed・8/16/32 Event・各40 queryでは候補on/offとも、展開48、Primitive検査96、kernel40で一定。一方、接地のEvent参照は288→576→1,152と経験数に比例した。表＋simple BFSは展開48、contract検査184、kernel24。いずれも40/40正解、誤受理0で、計測あり/なしと復元後の完全結果は同じ。

node数が一定でも、支持Eventを再走査する接地処理は線形増加する。これを凝縮やquery仕事量低下とは呼ばない。計数は選択した操作に限定され、初期role誘導・index内部・graph隣接探索・CPU時間全体は含まない。Event参照はmemory内の論理取得で、disk readではない。単位の違うcounterを足して速度比較しない。8–32 Eventの結果を100kへ外挿しない。

次にjoint役割対とidentity等値を保持する再構築可能な接地read modelを作り、全証拠経路と完全結果、追加学習、復元、役割交差反例を照合する。構築/保存コストも測り、強い表と候補採用gateを維持する。

## 简体中文

新增`compose_to_effect(..., search_diagnostics=work)`可选query诊断dict，每次重置。直接计数普通queue展开、Primitive检查、可用候选、后续action、role匹配plan、macro step尝试、transition-kernel调用及接地成功Event获取。不改变完整CompositionResult、保存schema或学习状态。macro普通node展开为零时仍单独计量step/kernel工作。

固定v2 fixture三个seed、8/16/32 Event、各40 query，两候选模式展开48、Primitive检查96、kernel40不变，而接地Event访问288→576→1,152随经验线性增加。表/simple BFS展开48、contract检查184、kernel24。三路径仍40/40、误受理零，计量前后及重载完整结果相同。

固定node数隐藏了支持Event重扫成本，不能称为凝聚或query工作量降低。计数仅覆盖所选操作，不覆盖初始role推导、index内部、graph邻接遍历及完整CPU时间。Event访问是内存逻辑读取，不是磁盘读取；不同计数单位不能相加推断速度，不将8–32 Event结果外推至100k。

下一步构建保留joint角色对及identity等值、可重建的接地read model，与全证据路径比较完整结果、增量学习、重载及角色交叉反例，测量构建/存储成本，保留强表及采纳gate。
