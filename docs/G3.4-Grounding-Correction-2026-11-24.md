# G3.4 — Explicit grounding correction / 明示的な接地訂正 / 显式接地修改

2026-11-24

日本語: Event→Primitiveの逆参照で、報告されたEvent訂正の影響先だけを接地再構築する `GroundingCorrectionTracker` を実装した。局所再構築CPU比は0.253–0.336だが、総CPU比は0.973–1.042で一貫した短縮はない。明示APIとして採用し、自動有効化しない。これは派生接地cacheの訂正であり、学習済み頻度・graph・candidateの訂正ではない。

English: `GroundingCorrectionTracker` rebuilds grounding entries through explicit Event-to-Primitive reverse dependencies. Local refresh CPU ratios are 0.253–0.336, but total ratios of 0.973–1.042 do not establish an overall win. Adopt as an explicit API only. It repairs derived grounding caches, not learned counts, graphs or candidates.

简体中文: `GroundingCorrectionTracker` 通过Event到Primitive反向依赖局部重建接地缓存。局部刷新CPU比为0.253–0.336，总CPU比为0.973–1.042，尚无一致整体收益，因此仅显式启用。它不修正已学习的计数、图或候选。

## Contract / 使用条件 / 使用约定

```python
from risa.engine.grounding_corrections import GroundingCorrectionTracker

tracker = GroundingCorrectionTracker(state)  # full initial build + dependencies
state.events_by_id[event_id].target = corrected_target
report = tracker.refresh([event_id])         # before any indexed query
```

- 全変更IDを渡す。未報告のin-place変更は検出できない。役割誘導規則等の依存不明時は `dependencies_known=False`。 / Supply every changed ID before querying; unreported mutations cannot be detected. Unknown rule/dependency changes require `dependencies_known=False`. / 查询前提交全部修改ID；无法检测未报告修改，规则等依赖未知时使用 `dependencies_known=False`。
- 支持集合・Primitive object・indexの変更、欠落参照の到着、削除、未登録Event、広い波及は全再構築。既定の広域判定は支持参照数の50%超で、実測最適値ではない。 / Structural changes, missing/deleted/untracked evidence and wide fan-out fall back. The default threshold is over 50% of support references, a heuristic rather than an optimized cutoff. / 结构变化、缺失/删除/未跟踪证据和广泛传播回退全重建；50%支持引用阈值为启发式，非最优测量值。
- 影響先はrows不変でも校正・hit履歴を失効し、無関係entryを保持する。合計lookup予算の残高内で再構築する。逆参照の追加メモリはこのlookup予算に含まれない。 / Reset affected calibration/hits even with unchanged rows; preserve untouched entries and the lookup-container cap. Dependency metadata is additional memory outside that cap. / 即使rows不变也清除受影响校准/命中历史，保留无关entry及lookup上限；依赖元数据额外占用内存。
- 支持ID検査は毎回全Primitiveを走査する。O(delta)の保証ではない。通常ingestionと保存schemaは変更しない。 / Every refresh validates all Primitive support sets; this is not O(delta). Normal ingestion and persistence schema are unchanged. / 每次检查全部Primitive支持集合，并非O(delta)；常规摄入及保存schema不变。

Independent/coupled worlds contain 96 Events each; the concentrated world contains 256. Six processes, two budgets and three worlds produce 36 trajectories with seven correction/restoration steps. Independent states receive identical edits. The manifest records generator source hashes, Python/RNG version, seeds, input digest, edit order and old/new field values; replay into a third state is checked at every step. Authoritative evidence is retained.

独立/耦合world各96 Event，集中world256 Event；6 process、2预算、3 world，共36轨迹，每条7个修改/恢复步骤。独立state接受相同修改；manifest记录生成器摘要、Python/RNG版本、seed、输入摘要、顺序及字段旧新值，每步在第三state重放验证，不以seed替代权威证据。

32,256件の完全結果照合で差0。各段階で `to_dict()`、実保存bytes、復元後queryを比較。跨processでは既存のgraph edge格納順だけを正規化した保存digestと結果digestが一致。校正失効、共有支持、同件数の支持変更、append、欠落Event到着、ID改名・格納順変更は単体回帰でも検証。

All 32,256 complete-result checks match. Every step compares authoritative dictionaries, exact saved bytes within process and restored queries. Cross-process saved digests normalize only existing graph-edge storage order; result digests also match. Unit regressions cover calibration, shared evidence, same-size support changes, append, missing arrivals, evidence-ID renaming and storage order.

32,256次完整结果比较无差异；每步对比权威字典、process内保存字节和恢复查询。跨process保存摘要仅规范既有graph edge存储顺序，结果摘要亦一致。单测覆盖校准、共享证据、同大小支持变化、追加、缺失到达、证据ID改名及存储顺序。

Full-scan oracle audits and manifest replay assertions are verification work, excluded from execution totals; scan query CPU is timed separately. Local Event reads fall from 96 to16 and 256 to64; fallback is3/7 steps. Dependency bytes estimate reachable Python metadata, excluding source Primitive objects and counting shared strings once, not exclusive overhead/RSS/peak. Manifest JSON adds17,816–24,305 bytes. Save/load noise affects totals; no universal speedup is claimed.

局部Event访问由96降至16、256降至64；fallback为3/7。依赖bytes为可达Python元数据估算，排除源Primitive对象、共享字符串只计一次，并非独占增量/RSS/峰值。manifest JSON另占17,816–24,305 bytes。保存恢复波动影响总比值，不宣称普遍提速。
