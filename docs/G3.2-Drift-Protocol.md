## Question / 問い / 问题

日本語: A→B→Aの環境変化で、構造の分裂・統合・休眠が、旧知識の保持、回復速度、局所更新、Replay費用にそれぞれ何を寄与するか測る。予測精度だけで採否を決めない。

English: Measure what splitting, merging and dormancy each contribute to prior-knowledge retention, recovery, local updates and Replay cost during A→B→A drift. Accuracy alone is not the decision criterion.

简体中文: 在A→B→A环境变化中，分别测量分裂、合并与休眠对旧知识保持、恢复速度、局部更新和重放成本的贡献；不只凭预测准确率决定是否采纳。

## Mechanism boundary / 機構境界 / 机制边界

The current code has distinct mechanisms that must not be silently grouped:

| Mechanism | Current path | Intervention needed |
| --- | --- | --- |
| Primitive context split | `TrainingOptions.enable_adaptation` → `execute_safe_adaptations` → `SPLIT_CONTEXT` | A split-only switch; leave `REPAIR_TRANSITION` fixed in every arm. |
| Candidate specialization | `propose_context_derivations` → `specialize_candidate` | A generation switch independent of merge. |
| Candidate merge | `propose_context_derivations` → `merge_candidates` | A merge switch and a fixed eligible sibling pool in every arm. |
| Candidate dormancy | `_dormant_replaced_ancestors`, plus `set_candidate_dormant` | A candidate-dormancy switch; preserve adopted ancestors when disabled. |
| Graph-node metabolism | `decay_nodes` | Hold constant and report separately; the existing `enable_metabolism=False` also disables decay and is not a candidate-dormancy ablation. |

The present `risa_no_splitting` control disables all safe adaptations, and the G1/G2 drift fixture does not exercise candidate merge. Its existing drift rows cannot identify the requested causal effects. A merge-only arm needs sibling scopes because automatic merge consumes specialized siblings. Capture the **same evidence-backed context scopes** before the phase A checkpoint in all arms, then rebuild their support from current primary Events; the split switch controls only discovery of new scopes after that checkpoint. Record this design choice explicitly in results. Do not inject answer labels or evaluation episodes into the pool. Proposal availability alone does not establish inference availability: adopted status must be audited after every online observation.

| Arm | New split | Merge | Candidate dormancy |
| --- | ---: | ---: | ---: |
| Full | on | on | on |
| Split only | on | off | off |
| Merge only | off | on | off |
| No split | off | on | on |
| No merge | on | off | on |
| No dormancy | on | on | off |
| None | off | off | off |

The five requested arms are retained; `No split` and `No merge` add the one-factor contrasts needed to isolate each mechanism against Full. All arms receive identical Event order, observations, candidate eligibility, inference budget, Replay schedule and planner configuration. Log executed split/merge/dormancy counts; a zero opportunity or zero execution means the contrast is non-informative, even if its accuracy differs.

## Episode and measurement contract / 測定契約 / 测量协议

1. Freeze five seeds, worlds, phase lengths, development/final partitions and metric thresholds in a versioned manifest before inspecting final results. Use independent held-out probes for each phase and never learn or Replay probe Events. Online observations follow predict → score → observe; delayed observations are applied only when due.
2. Include a **same-context reversal** world, where B conflicts with A, and a **context-observable** world, where specialized structures can route by context. Include recurring and distractor structures so touch ratio has a meaningful denominator. Ensure each mechanism has eligible opportunities in development; otherwise redesign the world before freezing final.
3. At the end of A1, measure A1 accuracy on a fixed held-out A probe panel and snapshot the entire state. At B entry and A2 return, probe before any new-phase observation. Continue probing after each newly observed Event; probes never update the model.
4. `recovery_events`: number of **newly observed** Events after a phase boundary until a prespecified rolling probe window first reaches at least 95% of that arm's A1 accuracy (for B use its prespecified stable-B reference). Report B and A2 separately, and censor at the phase budget rather than converting non-recovery to zero. Report coverage and all-query success with abstentions counted as failures.
5. `retention_after_return`: A-probe all-query success immediately at A2 entry, before A2 learning, divided by A1 A-probe success. Also report both absolute accuracies; a low A1 baseline must not create a flattering ratio.
6. `adaptation_touch_ratio`: distinct pre-boundary knowledge structures with a material semantic or weight change during the phase, divided by all pre-boundary eligible structures. Count graph edges/nodes, primitives and candidates separately and as a deduplicated total. Exclude Event record nodes and edges incident to them from the knowledge denominator. Exclude newly created structures from this denominator, but report their counts and bytes separately. Define a canonical before/after fingerprint that omits timestamps, access counters and derived indexes; do not equate every Event append with a structural rewrite.
7. `replay_cost_per_recovery`: total Event inspections and Event reapplications by Replay from boundary through recovery; report each separately. Include unsuccessful phases as censored costs through phase end. Instrument actual processed Events rather than multiplying configured window size by calls.
8. Report pre-update success by phase, false generalization, stored bytes/Event, active and dormant structure counts, candidate lineage, and wall time as secondary measures. Compare paired seeds/episodes with 95% intervals. Retain failures and ambiguous results; no post hoc gate relaxation.

The primary causal contrasts are Full versus No dormancy, Full versus a no-merge arm, and Full versus a no-split arm. The requested Split only, Merge only and None arms show sufficiency and interactions. Interpret dormancy's retention gain separately from any change in coverage or false generalization.

## Model/planner separation / モデルと探索の分離 / 模型与规划分离

Run a fixed prediction panel first, without planning. On planning tasks, use the same query and independent environment oracle for four cells: oracle world model + RISA planner; RISA world model + fixed simple planner; RISA world model + RISA planner; grounded transition table + RISA planner. Keep supplied-transition and learned-transition tracks separate. A planner gain must not be reported as concept formation.
