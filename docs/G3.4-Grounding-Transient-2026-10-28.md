# G3.4: Transient drift and count hints / 短期変化と件数のヒント / 短期漂移与计数提示

## 実装 / Implementation / 实现

`GroundingCountTrigger(factor=2, min_delta=16)` を追加した。比較可能な完了区間のquery件数を `observe(count, sampled=...)` へ渡す。前区間からの絶対差16以上かつ件数比2倍以上（増加・減少の両方向）なら、次の `GroundingSampleSchedule.next_window(force=...)` に渡すヒントを返す。0件からの増加・0件への減少は絶対差の下限を満たす場合に対象。初回は基準値だけを設定する。

収集済み区間の変化はその標本に反映されているため、`sampled=True` は追加の強制収集を抑止する。通常queryへのフックや永続データを追加しない。保持状態は直前件数のみで、毎queryの追加計数は呼び出し元が既に件数を持つ場合には不要。固定件数で区切る区間では同じ件数しか観測できないため、このトリガーに意味はない。固定時間など比較可能な区間を使う。

Explicit `GroundingCountTrigger` compares completed-window counts using both an absolute floor and a multiplicative threshold. Its boolean is a hint for the **next** window, never for traffic already missed. A sampled window suppresses redundant forced refresh for its own count change. Only the previous count is retained; no query hook or persistence changes. Counts must describe comparable windows; fixed-count windows provide no signal. Defaults are experimental settings, not tuned production thresholds.

显式计数提示比较已完成区间的绝对差及倍数，布尔结果仅用于下一窗口。已采样窗口抑制自身计数变化导致的多余强制刷新。只保留前次计数，不增加query钩子或持久数据。区间必须可比，固定件数窗口无法提供信号。阈值仅供实验，非生产调优结果。

```python
schedule = GroundingSampleSchedule(interval=4)
trigger = GroundingCountTrigger()
force_next = False
# At each boundary, before seeing the next window's traffic:
sampler = schedule.next_window(force=force_next)
# Caller runs the window and installs observation only if sampler is not None.
# Once the window has completed:
force_next = trigger.observe(completed_query_count, sampled=sampler is not None)
```

同件数の役割・identity変化を検出する仕組みではない。query件数変化とbinding分布変化の関係も保証しない。分布変化が1区間で戻ると、件数変化を見て次に収集してもその変化は既に終了している。

Equal-count role/identity drift is invisible, count changes do not imply binding drift, and a one-window transient can end before the forced collection begins. / 同计数的角色/identity漂移不可见，计数变化不保证binding漂移，单窗口变化可能在强制采样前已结束。

## 品質と因果関係 / Quality and causality / 质量与因果关系

今回のヒントは短期変化の捕捉率を改善するものではなかった。位相1の変化は周期から外れ、件数が増えても検知はその区間終了後なので、強制収集する区間2には既に元へ戻っている。位相4では通常周期でも変化を採取できるが、その後に元へ戻った区間5の件数減少を見て区間6で強制収集でき、古い標本を更新できる。同件数ならこの判断は働かない。収集済み区間の件数変化を抑止することで、区間4自体の変化による区間5の追加収集は行わない。この省略は費用を減らす一方、復帰の追従を1区間遅らせる。

The hint does not improve transient capture in this protocol. At phase1, forced collection starts after the transient ends. At phase4, periodic sampling already captures it; a later completed-count drop can refresh stale samples in window6. Equal-count drift remains invisible. Suppression of already-sampled count changes saves a possible window5 collection but delays recovery by one window; this is a cost/latency tradeoff, not a universally superior policy.

本协议中提示不提高短期变化捕捉率：相位1强制采样时变化已结束；相位4周期采样已捕捉变化，随后计数下降可在窗口6刷新旧样本。同计数漂移不可见。抑制已采样计数变化避免潜在的窗口5采样，但将恢复延迟一窗口，是成本/延迟取舍，非普遍最优。
