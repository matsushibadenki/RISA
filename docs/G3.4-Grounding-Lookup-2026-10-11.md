# G3.4 Joint role/identity lookup / 接地検索索引 / 接地查询索引

## 日本語

同一actor役割へ多数のwitnessが集中した場合の線形走査を、actor役割→target役割→identity許可ビットの索引へ置き換えた。1行のwitness内だけで役割対を展開する。異なる行のactor・target・identityを独立に結合しない。同一役割対のidentity許可はORで集約できる。検索の条件は複数役割の全一致ではなく、従来どおり各側のいずれかの役割が同じwitnessに含まれること。

identity不明は一致・不一致の両方を許可する。target役割の空行はtarget条件のwildcardとして別枠に保持し、target未指定時にはactor単位の集約を使う。型付きactor証拠がある場合に型なし行でactor条件を迂回できない規則も保持する。元のwitness行は検証・正規payload計測用に残し、新規行のみ索引へ追加する。保存ファイルに索引は含めず、訂正・Primitive置換・split時の無効化／再構築契約は従来どおり。

検索は保存witness数Wの走査から、queryのactor役割数Aq、target役割数Tqに応じた辞書参照（最大O(Aq × (1 + Tq))）になる。構築・新規witness追加には各行のactor役割数A、target役割数Tの役割対展開O(A × T)が加わる。したがって役割の多い証拠ではメモリ・更新費用が増える。大量役割を無条件に展開する上限方針は今回導入しない。`grounding_lookup_probes`を新設し、従来の`grounding_signature_checks`とは区別する。

比較対象は全走査、変更前の差分集合＋線形検索、今回の差分集合＋役割対検索の3方式。変更前実装を`experiments/grounding_linear_reference.py`へ固定した。8/64/256 witness、各側1/4役割、3反復の循環順序（18軌跡）で、8回の追加と各48 queryを交互に実行する。新規・既知witnessは各4回。queryは成功例、identity反転、複数役割の一部一致、未知役割、target/identity未指定、候補on/offを含む。全CompositionResult、更新ごとの保存用内容、実保存バイト列と復元後の結果を照合する。構築の計量にtracemallocを重ねず、別の構築で割当量を測る。

メモリはindexから到達できるPythonオブジェクトをidで重複排除して`sys.getsizeof`を合計し、元Primitiveへのreferencesを除外した推定量。共有文字列を含み得るため厳密な専有heapでもRSSでもない。tracemallocの構築保持量とピークもJSONに残す。計測は固定hash seed=0の単一process、合成fixtureであり、他world・query密度への一般化を主張しない。

## English

Replace linear witness scans with an actor-role → target-role → identity-mask lookup. Expand pairs only within one witness; do not independently join actor, target and identity evidence. Preserve existential multi-role matching, absent-target and unknown-identity wildcards, and mixed typed/untyped behavior. Keep canonical rows, update the lookup only for new rows, and preserve persistence/invalidation contracts.

Query work depends on supplied role combinations, at most O(Aq × (1 + Tq)), instead of stored witness count. Building/appending new rows adds O(A × T) pair expansion and memory overhead. Record lookup probes separately from row checks. No universal role-expansion threshold or automatic backend switching is introduced.

Compare scan, frozen linear incremental and lookup incremental across 8/64/256 witnesses, 1/4 roles per side and three rotated repetitions. Each trajectory alternates eight appends (four new/four existing witnesses) with48 queries covering partial multi-role matches, identity reversal, unknown roles, omitted bindings and candidate on/off. Verify complete results, serialized updates, actual saved bytes and reload results. Time builds separately from tracemalloc allocation passes. Reachable-object size excludes source-primitive references and deduplicates object identities; it may count shared strings and is neither exclusive heap nor RSS. Results use one process with hash seed0 and do not establish universal selection thresholds.

## 简体中文

将witness线性扫描替换为actor角色→target角色→identity掩码索引。只在同一witness内展开角色对，不独立组合不同证据中的actor、target与identity。保持多角色的存在性匹配、无target及未知identity通配、混合有类型/无类型行为。保留原始行，仅新增witness时更新索引，保存与失效约定不变。

查询最多O(Aq × (1 + Tq))次角色查找，不依赖保存的witness数量；构建及新增行增加O(A × T)角色对展开与内存成本。区分lookup probes与原行检查数，不引入通用展开阈值或自动切换。

比较全扫描、冻结的旧线性差分、新查询索引差分：8/64/256种witness，每侧1/4角色，三次轮换，共18轨迹。每轨迹8次追加（新旧各4次），每次48 query，覆盖部分多角色匹配、identity反转、未知角色、省略绑定及候选开关。验证完整结果、序列化、实际保存字节及恢复结果。tracemalloc在独立构建中运行，不混入构建计时。可达对象估算排除源Primitive引用并按对象id去重，但可能计入共享字符串，不等于专有heap或RSS。使用固定hash seed0的单process合成实验，不推导通用选择阈值。
