# G3.4 compositional holdout and dependency counterexamples

## English

### Scope and fixed development contract

Inspired by [Memory Mosaics, Sections 4–5](https://arxiv.org/html/2405.06394v3#S4), test whether known local
transitions support an unseen complete path while preserving dependencies. This is not a reproduction of
predictive disentanglement or a test of learned latent factors. Roles, preconditions, numeric thresholds,
deltas and atomic effects are supplied in identical structured Events to all learners.

[Manifest](../experiments/g3_compositional_holdout_manifest.json) fixes seeds 701/809/907, two semantic worlds,
8/16/32 training episodes (24/48/96 Events), three-step search, candidate advantage ≥0.05 and zero allowed
RISA false accepts. It was saved before the first run; this is a reviewed development fixture, not external
preregistration or an untouched final. Seeds vary entity identifiers, not semantic rules. No held-out labels
are passed to training or adoption. Each branch × binding family spans both sources at every checkpoint.

### Worlds and oracle

Train only `prepare_a → bridge → finish_a` and `prepare_b → bridge → finish_b`.
Hold out the crossed whole paths `prepare_a → bridge → finish_b` and the reverse. Every adjacent action pair
in each held-out path already occurs in training; no novel successor edge is supplied by an oracle.

Both preparations require `connected` and `token`, consume the token and produce `staged` plus their ticket.
The bridge consumes `staged` and produces `ready`. Each finish consumes `ready` and atomically produces its
`done` effect plus `receipt`. Every stage requires one energy unit and consumes it. A successful path needs
three units, even though each isolated stage is applicable with two.

- Independent world: either finish accepts either preparation's ticket; it only requires `ready`.
- Coupled world: `finish_a` additionally requires `ticket_a`, and `finish_b` requires `ticket_b`.

Each world has 20 held-out cases: four seen-path positives, four crossed paths (positive only in the independent
world), and two each of crossed roles, wrong identity equality, missing token, missing connected state, shared
resource exhaustion and missing actor role. Valid binding families are operator/remote-unit with distinct
identities and autonomous/self-unit with equal identities. The panel's Boolean oracle is explicit in
`heldout_cases`; neither learner, training generator nor transition kernel computes its labels. Training and
evaluation share the documented vocabulary, not the label computation. A separate regression checks atomic
receipt production, ready consumption and final energy. Panel quality measures goal reachability, not every
field of an environment rollout.

### Arms

| Arm | Purpose |
| --- | --- |
| Native RISA, candidates on/off | Existing production composer and unchanged adoption rules |
| Event-derived factorized contract table | Strong baseline; retains joint role/equality and transition constraints |
| RISA learned ordinary primitives + shared BFS | Same BFS as the table; native candidates excluded explicitly |
| Whole-path table | Same contracts/BFS, additionally requires an observed complete action path; restrictive control |
| Role marginals | Drops only the joint role/equality witness, retaining individual observed marginals |
| Reset resource | Restores initial energy at each stage, dropping resource dependence across stages |
| Drop ticket | Removes the finish's ticket prerequisite, dropping the cross-stage state dependency |

The final three arms are deliberately invalid independence assumptions, not strong baselines. They should
expose false accepts on their targeted counterexamples. The shared BFS uses observed episode successors for
the table and learned graph successors for the RISA adapter. RISA contracts use actual learned adopted ordinary
primitives plus same-Event binding witnesses. This isolates model differences under a shared search procedure
but is not an implementation-equivalent replacement for native RISA selection/scoring. No learned roles,
automatic independence discovery or candidate adoption benefit is inferred from this setup.

### Measurements and decision rules

Record per-category correct/positive-correct/false-accept counts, complete native-result reload equality,
instrumented/uninstrumented equality, evaluation immutability, split audits, logical storage bytes, primitive
and candidate counts, adoption labels and search counters at every checkpoint. Keep raw Events in both storage
payloads; bytes are not equal-functionality resident memory or measured file sizes. Shared-BFS model-building
work is outside query counters; native counters also omit some role/index/graph work. Do not sum different
counter units or infer latency from them.

An all-reject system cannot pass positive probes. Quality must pass both unseen-path and dependency panels.
Candidate advantage is relative to the strong factorized table, never just the whole-path or unsafe arms.
If no candidate is adopted, candidate-on/off is an opportunity control. Keep the failed advantage gate visible.
Repeated checkpoints describe data requirements but do not establish a minimum sample count below the first
checkpoint, decreasing cost, structural growth or generalization to different semantic rules. G3.4 remains
open until quality and marginal storage/search improvements hold together under independent evaluation.

```sh
python3 -m experiments.compositional_holdout
python3 -m pytest -q tests/test_compositional_holdout.py
```

## 日本語

Memory Mosaicsの考え方を参考に、既知の局所遷移から未知の全経路を合成できるか、依存条件を壊さずに検証する。
学習はa→bridge→aとb→bridge→bだけ、評価は交差経路も含む。独立世界では交差が成立し、依存世界では前段のticketと
後段の必要ticketが一致しなければ棄却する。全段階でenergyを1ずつ消費し、初期2では3段階を完了できない。
同じEventに支持された役割対・identity等値、token/connected不足、actor役割不足を反例に含める。

manifestを初回実行前に固定し、3 seed・2世界・24/48/96 Event・各20 caseで比較する。
seedはentity名のみを変更する。前提・delta・役割は明示され、未知潜在因子の発見や論文再現とは主張しない。
明示oracleはlearnerや遷移kernelから独立した真偽表。ID/entity・全経路の重複0と、局所遷移の観測済みを監査する。

RISA候補on/off、制約保持の因子化表、同じBFSを使うRISA通常Primitive、完全経路表を比較し、役割の周辺集合化・
資源リセット・ticket条件除去を反例感度の対照にする。後三者の弱さをRISAの優位と扱わない。
候補利得≥0.05・誤受理0を維持し、採用ラベルや強制採用を追加しない。採用0なら機会不足controlとする。
Boolean品質、正例成功、完全結果の復元/計測一致、不変性、保存量、構造数、仕事量を記録する。
同一BFSのadapter構築費用はquery計数外、payloadは同等機能memory比較ではない。
必要観測数の下限、意味規則への汎化、保存/検索費用の減少、凝縮はこの開発fixtureだけでは確定しない。

## 简体中文

借鉴Memory Mosaics，测试已知局部转移能否在保留依赖的前提下组成未知完整路径。
只训练a→bridge→a及b→bridge→b，评估包含交叉路径。独立世界允许交叉；依赖世界要求前段ticket与后段条件一致。
每步消耗一个energy，初始两个不能完成三步。反例覆盖联合角色、identity等值、token/connected缺失及actor角色缺失。

首次执行前固定manifest：三个seed、两个世界、24/48/96 Event、每面板20 case。seed仅改变entity名称。
角色、前提和delta均明确提供，不声称发现潜在因子或复现论文。独立真值面板不由训练器或转移kernel计算。
审计ID/entity及完整路径无重叠，同时确认局部转移均已观察。

比较RISA候选开关、保留约束的因子化表、共享BFS的RISA普通Primitive及完整路径表。
角色边际化、资源重置、删除ticket只是反例敏感度对照，不作为优势证据。
保持候选优势≥0.05与误受理零门槛，不增加采纳标签或强制采纳；采纳零属于机会不足对照。
记录Boolean质量、正例成功、完整结果恢复/计量一致、不变性、存储、结构及工作量。
共享BFS的adapter构建成本不在query计数内，payload不等于等功能内存。该开发fixture不能独立证明最低样本数、
新语义规则泛化、成本下降或凝聚。
