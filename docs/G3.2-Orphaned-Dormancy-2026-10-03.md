# G3.2 unchanged-parent reactivation after replacement expiry

## English

### Implementation

`TrainingOptions(reactivate_validated_orphaned_ancestors=True)` enables a discovery-time repair of candidate dormancy. The default remains disabled for a controlled comparison. This is a training option, not validation inheritance and not a change to persisted schema v6.

A candidate can wake only when it was an adopted dormant ancestor of a previously final-validated replacement with the same action, target role and effects; it remains adopted with nonempty final validation; its ID, schema, typed roles, supporting/counterexample Event sets, development/final validation IDs and parent IDs and semantics are unchanged; and no current active adopted descendant still replaces its transition. Missing candidates, changed evidence, stale adoption, another active replacement and manual dormancy without a known validated replacement do not qualify. The routine never adopts proposed/rejected candidates or copies validation to newly generated IDs. Inference indexes rebuild after reactivation. The altered dormant bit persists through ordinary state serialization.

Root evidence digests can change when new evidence arrives outside a specialized candidate's scope. Digest equality is therefore not required: the scoped candidate's own support/counterexamples and validation must be unchanged, and its parent IDs and schemas/typed roles/derivation types must retain the same semantics. A changed parent semantic blocks reactivation. This uses the existing scoped validation restoration boundary; it does not validate an extended scoped candidate. Tests explicitly cover this distinction.

This is deliberately narrow: unchanged existing validation can support a fallback, but changed candidate evidence still requires independent revalidation. The opt-in option is supplied for each training call, like the other training switches; it is not a policy automatically restored by loading a state.

### Paired development evaluation

The paired manifest runs the previous five seeds × seven arms with the option off and on: **35 paired rows / 70 runs**. Both sides retain the same Events, exact-context drift probes, nuisance diagnostic probes, B-boundary validation schedule, 1,200-label cap and bootstrap gates. Actual labels consumed and complete adoption decisions match for every pair. Strong latest/count two-hop context-subset tables remain in both control outputs with zero adoption labels.

| Full arm A nuisance correctness across five seeds | Disabled | Enabled |
| --- | ---: | ---: |
| After B validation | 80/120 | 80/120 |
| After first A2 Event | 16/120 | **48/120** |
| A2 exit | 0/120 | 0/120 |

Four seeds regain eight correct predictions each after the first A2 update. In the fifth seed the merge remains valid at that update, so its two parents stay dormant and the existing 16 correct predictions are unchanged. No other arm's checkpoint correctness changes. This matches the first-update accuracy of no-dormancy/no-merge, rather than demonstrating a new structural advantage. At A2 exit, changed evidence invalidates all relevant adopted candidates and neither option retains nuisance correctness.

The fix consumes **zero additional labels**. It preserves exact-context B recovery counts 5/5/6/5/7 and A2 recovery zero. No independent-final claim, nuisance recovery claim or A1-retention claim follows: A1 nuisance accuracy was zero, and B validation supplied the useful A scope. Strong subset tables still achieve A/B 120/120 at B and A2 exit without adoption labels. The option repairs one transient fallback gap; it does not solve candidate validation lifetime or show merge benefit.

All 350 checkpoints compare complete PredictionResults after JSON reload. Tests cover an active replacement, expiry, changed counterexamples, missing final validation, changed parent semantics, out-of-scope root evidence updates, independent active replacement, unrelated manual dormancy, idempotence and actual paired online behavior. Raw JSON retains the ordinary drift metrics, label IDs, adoption results and checkpoint comparisons.
