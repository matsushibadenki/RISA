# G3.2 Candidate Context Transfer — Development Control

## English

This control tests whether adopted candidate structures change decisions when
queries contain context combinations absent from training. Six A1 Events and
1,200 supervised adoption labels are used per seed; adoption labels test
applicability, while scoring probes use separate IDs. There is no B phase or
return cue, so this experiment does not measure recovery or retention.

Five development seeds each receive three panels of 24 probes. Actor and target
entities are unseen. Exact-context probes retain the learned context. Transfer
probes add a distinct unseen nuisance tag without changing the latent outcome.
Conflict probes combine indoor and outdoor: the fixture defines the expected
behavior as abstention because the two learned rules disagree. This abstention
policy is a development contract, not a universal semantic rule.

| Panel (120 probes) | RISA | RISA without candidates | Latest/count exact tables | Subset table |
| --- | ---: | ---: | ---: | ---: |
| Exact context: effect accuracy | 100% | 100% | 100% | 100% |
| Unseen nuisance: effect accuracy | 66.67% | 0% | 0% | 100% |
| Conflicting context: expected abstention | 0% | 100% | 100% | 100% |

Removing the adopted merge changes 80/120 nuisance predictions and reduces
accuracy to zero. Reactivating dormant ancestors changes none. This establishes
a merge readout contribution in this fixture, but the active specialized
parents can provide the same predictions. It does not establish a merge benefit
over those parents or a dormancy benefit.

The stronger table matches every observed context subset, uses the most specific
matches, and abstains if their outcomes disagree. It receives the same Events
and query tags, no relevant-tag selector, and no adoption labels. Its 100%
transfer accuracy means beating exact-key tables here is insufficient evidence
for structural advantage. RISA has no adopted cold candidate, explaining the
remaining nuisance abstentions. The conflict panel also exposes candidate
predictions that exceed this fixture's intended applicability.

Next: retain the subset table in development comparisons; define coherent
context combinations and an observable return cue that does not directly select
a memorized key before implementing a full drift world. Freeze opportunities,
label budgets, and applicability behavior before independent final evaluation.

## Context conflict guard — 2026-10-03

English: Added a separate opt-in evaluation policy that compares majority
multi-effect outcomes across the most specific observed context subsets. With
no extra labels, it abstains on all 120 conflict probes, preserves 80/120 correct
nuisance predictions, and preserves 120/120 exact-context predictions. Exact
context evidence delegates to the existing predictor; a more specific joint
context overrides disagreement among less specific scopes. Unrelated roles are
excluded and multi-effect outcomes are kept together. This policy tests the
fixture's abstention contract and does not establish an intrinsic distinction
between conflicting and compatible domain contexts. It uses supplied roles
rather than induced roles. The reference implementation scans six Events per
query, costing 720 Event reads per 120-probe panel. Core inference remains
unchanged; scaling and independent validation are prerequisites to adoption.

日本語: 独立した実験用衝突ガードを追加した。最も具体的な既知context部分集合ごとに、複数効果をまとめた結果の多数決を比較する。追加ラベル0件で矛盾probeは120/120件棄権し、未見タグ80/120件正解、完全一致120/120件正解を維持した。完全一致時は現行予測器に委譲し、より具体的な共同contextは浅いcontextの衝突より優先する。別roleは除外する。fixtureの棄権契約を評価する方針であり、文脈の意味的な矛盾を自動理解した証拠ではない。入力済みroleのみを使い、queryごとに6 Event、各120-probe条件で720 Event参照を要する。本体採用前にはスケールと独立評価が必要である。

简体中文: 添加独立的可选实验冲突保护策略，比较最具体的已观察情境子集中的多数完整结果，并将多个效果作为整体处理。无需额外标签即可在120/120个矛盾探针上弃权，同时保留未知标签80/120及完全匹配120/120的正确预测。完全匹配交给现有预测器，更具体的联合情境优先于较浅情境的分歧，并排除其他role。这仅验证fixture的弃权契约，并非自动理解情境语义矛盾的证据。仅使用输入role，每query扫描6个Event，每组120探针需720次Event访问；纳入核心前需完成规模及独立验证。

## Indexed audit scaling — 2026-10-03

English: Added `ContextConflictIndex`, an evaluation-only derived index updated
explicitly by its owner at ingestion and Event replacement. It stores context
outcome groups plus full provenance; queries do not read Event objects. The
transfer control now requires complete audit semantics and provenance equality
against the scan reference for every probe. Outcomes remain unchanged. This
index is not attached to the training state or used by the default predictor.
The conflict guard still uses the scan reference; the harness independently
checks indexed audits. Incremental replacement tests cover scope changes,
majority ties, duplicate ingestion, normalization and multi-effect outcomes.

| Events | Context growth | Scan Event reads / 3 queries | Indexed scope reads / 3 queries |
| ---: | --- | ---: | ---: |
| 1,000 | 3 reused scopes | 3,000 | 9 |
| 10,000 | 3 reused scopes | 30,000 | 9 |
| 100,000 | 3 reused scopes | 300,000 | 9 |
| 1,000 | unique scopes | 3,000 | 3,000 |
| 10,000 | unique scopes | 30,000 | 30,000 |
| 100,000 | unique scopes | 300,000 | 300,000 |

All six configurations preserve exact decisions and sorted provenance IDs.
These are work counters, not latency speedup factors. Building the index reads
N Events once. Evidence remains O(N); at 100k reused contexts the three queries
return 133,335 provenance IDs in total, so output cost also grows with evidence.
Unique contexts contain an unmatched instance tag, yielding no matching evidence
but still requiring a scan of all scopes for the selected action/role bucket.
Timings in the JSON are single observations and not adoption criteria. Full
training, graph construction, discovery, planning and persistence are excluded;
this does not complete G3.3 or establish structure condensation.

日本語: 明示的なingestion/置換更新を持つ評価用派生indexを追加した。全probeと1k/10k/100kの6構成で、走査版の判断と根拠IDを完全に再現した。3文脈再利用時は3 queryの300,000 Event参照を9文脈参照へ減らせるが、文脈がEventごとに増える場合は300,000文脈参照が必要である。この比は速度比ではない。index構築はN Event、出典保存はO(N)、100k再利用条件の出力も計133,335根拠IDを要する。ガード本体は走査版を使い、harnessでindex版との同値を独立確認する。学習・graph・候補発見・planner・保存のスケール証明ではなく、G3.3は未完了である。

简体中文: 添加需显式摄取及替换更新的评估派生索引。全部探针及1千/1万/10万的六种配置均完全复现扫描版的判断和来源ID。复用三个情境时，三个query的300,000次Event读取变为9次情境读取；每Event均产生新情境时仍需300,000次情境读取。这是工作量而非速度比。索引构建读取N个Event，来源存储仍为O(N)，10万复用情境配置输出共133,335个来源ID。保护策略仍采用扫描参考，由harness独立验证索引等价性。该结果不证明完整学习、graph、候选发现、规划及持久化的规模性能，G3.3仍未完成。
